# MatCause — 요구사항 명세 (Requirements)

> 소재·공정 결함 원인 판별 및 대응 피드백 에이전트
> 문서 버전 0.1 · 예선 제출용 초안

## 1. 문서 개요

### 1.1 목적
반도체/소재 기업의 품질·응용 엔지니어(FAE)가 불량 또는 고객 클레임을 받았을 때,
원인이 **소재 물성 한계(Material)** 때문인지 **공정 조건 문제(Process)** 때문인지를
자동으로 1차 분기하고, 정량적 근거와 대응안 초안을 리포트로 생성하는 웹 에이전트를 정의한다.

### 1.2 용어 정의
| 용어 | 정의 |
|---|---|
| FAE | Field/Field-Application Engineer, 품질·응용 엔지니어 |
| RFQ | Request For Quotation, 고객 요구 스펙 문서 |
| Triage | 이슈를 소재/공정 요인으로 1차 분류하는 단계 |
| MP | Materials Project (소재 물성 공개 DB) |
| SECOM | UCI ML Repository의 반도체 공정 센서 데이터셋 |
| OCAP | Out of Control Action Plan, 관리이탈 대응 절차 문서 포맷 |
| Gap Analysis | 요구 스펙과 현재 능력 간 격차 분석 |
| KB | Knowledge Base, 판단 근거·피드백 저장소 |

### 1.3 데이터 정직성 원칙 (필수 제약)
- **실존 공개 데이터만 사용한다.** 가짜/합성 데이터 생성 금지.
- Materials Project API, UCI SECOM 데이터셋, 공개 논문/문헌만 근거로 사용한다.
- 데이터가 특정 지표를 제공하지 않으면(예: MP 본 DB의 결함 형성 에너지 직접값 부재),
  이를 임의로 만들어내지 않고 "확보 가능한 프록시 지표"로 대체하며 리포트에 명시한다.

|---|---|---|

## 3. 기능 요구사항 (User Stories)

각 스토리는 `As a / I want / So that` 형식과 **EARS(Easy Approach to Requirements Syntax)** 기반 수용 기준을 가진다.
우선순위: **P0 = 핵심(예선 데모 필수)**, **P1 = 중요**, **P2 = 있으면 좋음(축소 가능)**.

---

### EPIC A — 이슈 입력 & Triage (분기)

#### US-A1 (P0) 이슈 입력
> As a 품질 엔지니어, I want RFQ 또는 불량 현상을 텍스트/파일로 입력하고 싶다, so that 분석을 시작할 수 있다.

수용 기준
1. WHEN 사용자가 텍스트를 입력하고 제출하면 THEN 시스템은 이슈를 정규화된 IssueRequest 객체로 저장한다.
2. WHEN 사용자가 파일(.txt/.md/.pdf/.csv)을 업로드하면 THEN 시스템은 텍스트를 추출하여 IssueRequest에 병합한다.
3. IF 입력이 비어 있으면 THEN 시스템은 제출을 거부하고 안내 메시지를 표시한다.
4. WHERE 입력에 전기적 특성 수치(예: 누설전류, 유전율)가 포함되면 시스템은 이를 구조화 필드로 파싱을 시도한다.

#### US-A2 (P0) 소재/공정 Triage 분류
> As a 엔지니어, I want 이슈가 소재 요인인지 공정 요인인지 확신도와 함께 분류받고 싶다, so that 어느 경로로 분석할지 판단할 수 있다.

수용 기준
1. WHEN IssueRequest가 제출되면 THEN Triage Agent는 `MATERIAL` / `PROCESS` / `AMBIGUOUS` 중 하나로 분류한다.
2. WHEN 분류가 완료되면 THEN 시스템은 0~1 범위의 확신도(confidence)와 분류 근거 텍스트를 함께 반환한다.
3. IF confidence가 임계값(기본 0.6) 미만이면 THEN 결과를 `AMBIGUOUS`로 표시하고 두 경로를 모두 제안한다.
4. THE 시스템은 분류 결과를 LLM(AWS Bedrock)과 규칙 기반 신호(키워드·수치)의 조합으로 산출한다.
5. WHEN 사용자가 분류를 수동으로 override하면 THEN 시스템은 사용자가 선택한 경로로 진행한다.

### EPIC B — 소재 요인 경로 (3-A) 【팀 핵심 강점, 최우선】

#### US-B1 (P0) 후보 소재 물성 조회
> As a 소재 담당, I want 이슈와 관련된 소재의 물성을 Materials Project에서 조회하고 싶다, so that 정량 근거를 확보한다.

수용 기준
1. WHEN 경로가 `MATERIAL`이면 THEN 시스템은 이슈에서 화학식/조성/물질군을 추출하여 mp-api로 조회한다.
2. THE 시스템은 확보 가능한 지표(formation energy, energy above hull, band gap, density, 대칭성 등)를 조회한다.
3. IF Materials Project가 결함 형성 에너지 직접값을 제공하지 않으면 THEN 시스템은 안정성 프록시(energy above hull 등)를 사용하고 리포트에 그 한계를 명시한다.
4. IF API 키가 없거나 호출이 실패하면 THEN 시스템은 사전 캐시된 공개 데이터로 폴백하고 데이터 출처·시점을 표시한다.

#### US-B2 (P0) 리스크 산정
> As a 엔지니어, I want 조회된 물성으로 소재 리스크를 정량 산정받고 싶다, so that 소재가 문제인지 판단한다.

수용 기준
1. WHEN 물성이 확보되면 THEN 시스템은 각 지표를 정규화하여 0~100 리스크 스코어로 환산한다.
2. THE 리스크 스코어는 가중합이며 각 지표의 기여도(breakdown)를 함께 제공한다.
3. THE 각 리스크 판정에는 사용된 수치와 판정 기준(threshold)을 근거로 첨부한다.

#### US-B3 (P0) 대체 소재 후보 랭킹
> As a 소재 담당, I want 대체 소재 후보를 근거와 함께 순위로 제시받고 싶다, so that 다음 실험 대상을 정한다.

수용 기준
1. WHEN 리스크 산정이 끝나면 THEN 시스템은 유사 조성/물질군에서 대체 후보를 조회해 랭킹한다.
2. THE 랭킹 결과 각 후보는 정량 지표, 개선 예상폭, 트레이드오프를 포함한다.
3. THE 랭킹의 정렬 기준과 가중치는 리포트에 표기한다.

### EPIC C — 공정 요인 경로 (3-B) 【축소 가능 스코프】

#### US-C1 (P1) SECOM 데이터 로드 & 이상 변수 규명
> As a 공정 엔지니어, I want 공정 이상 변수를 SECOM 데이터 기반으로 규명받고 싶다, so that 어떤 센서 항목이 불량과 연관되는지 안다.

수용 기준
1. WHEN 경로가 `PROCESS`이면 THEN 시스템은 SECOM 데이터셋(1567×590, Pass/Fail 라벨)을 로드한다.
2. THE 시스템은 Pass/Fail 그룹 간 통계 검정(t-test/Mann-Whitney 등)과 특성 중요도(ML)로 이상 후보 변수를 도출한다.
3. THE 시스템은 클래스 불균형(약 1:14)을 명시적으로 처리(리샘플링/가중치)하고 방법을 리포트에 기록한다.
4. THE 결과는 상위 N개 이상 변수와 각 변수의 통계량·중요도를 제공한다.

#### US-C2 (P2) 이상 변수 → 원인 매핑
> As a 엔지니어, I want 규명된 이상 변수를 알려진 원인과 매핑받고 싶다, so that 조치 방향을 잡는다.

수용 기준
1. THE 시스템은 SECOM 변수가 익명화되어 물리적 의미가 없음을 전제로, 사용자 정의 매핑 테이블(변수→설비/공정 파라미터)을 참조한다.
2. IF 매핑 정보가 없으면 THEN 시스템은 "통계적 이상만 확인됨(원인 미매핑)"으로 정직하게 표기한다.
3. THE 매핑 근거는 사용자가 편집 가능한 KB 항목으로 유지한다.

### EPIC D — 리포트 생성 (4)

#### US-D1 (P0) 자동 리포트 생성
> As a FAE, I want 원인·근거·권장 조치·권장 검증 실험을 담은 리포트를 자동 생성받고 싶다, so that 고객 대응 문서를 빠르게 만든다.

수용 기준
1. WHEN 분석 경로가 완료되면 THEN 시스템은 Gap Analysis / OCAP 스타일 리포트를 생성한다.
2. THE 리포트는 (a)판정 원인 (b)정량 근거 (c)권장 조치 (d)권장 검증 실험 (e)데이터 출처를 포함한다.
3. THE 리포트의 모든 수치 주장에는 근거 데이터 출처(MP material id / SECOM 통계 / 문헌)를 링크·인용한다.
4. THE 리포트는 화면 표시 및 Markdown 내보내기를 지원한다.

#### US-D2 (P1) 근거 추적성(Traceability)
> As a 심사위원, I want 결론이 어떤 데이터에서 나왔는지 추적하고 싶다, so that 결과를 신뢰할 수 있다.

수용 기준
1. THE 리포트의 각 주장은 근거 아이템 ID로 원본 데이터(조회 응답/통계 결과)와 연결된다.
2. WHEN 사용자가 근거를 클릭하면 THEN 원본 수치·출처가 표시된다.

---

### EPIC E — 피드백 & 지식베이스 (5)

#### US-E1 (P1) 리포트 피드백 기록
> As a 엔지니어, I want 리포트를 확인·수정하고 그 피드백이 저장되길 원한다, so that 다음 진단이 개선된다.

수용 기준
1. WHEN 사용자가 리포트 항목을 수정/승인/반려하면 THEN 시스템은 피드백을 KB에 구조화 저장한다.
2. THE 피드백 항목은 (원본 판정, 사용자 수정, 사유, 타임스탬프, 이슈 컨텍스트)를 포함한다.

#### US-E2 (P1) 피드백 재활용(RAG)
> As a 엔지니어, I want 과거 피드백이 다음 진단에 참고되길 원한다, so that 같은 실수가 반복되지 않는다.

수용 기준
1. WHEN 새 이슈가 들어오면 THEN 시스템은 KB에서 유사 과거 사례·피드백을 검색하여 Triage/리포트 프롬프트에 주입한다.
2. THE 검색은 경량 벡터 검색(로컬 임베딩 인덱스) 기반으로 동작한다.
3. THE 주입된 과거 근거는 리포트에 "참고 사례"로 명시된다.

---

### EPIC F — 웹 데모 UI

#### US-F1 (P0) 대시보드 플로우
> As a 데모 관람자, I want 이슈 입력→분기→근거→리포트→피드백을 한 화면 흐름으로 보고 싶다, so that 전체 가치를 이해한다.

수용 기준
1. THE UI는 입력 → 분기 판단(확신도 표시) → 근거 데이터 → 최종 리포트 → 피드백 입력 단계를 순서대로 제공한다.
2. WHEN 각 단계가 완료되면 THEN 해당 결과가 시각적으로 표시된다(스코어 바, 표, 랭킹 등).
3. THE UI는 진행 중 로딩/에러 상태를 표시한다.

### EPIC G — 플러그인 아키텍처 (비기능적이지만 필수)

#### US-G1 (P0) 코어/도메인 분리
> As a 개발팀, I want 코어 엔진과 반도체 도메인 플러그인이 명확히 분리되길 원한다, so that 다른 산업 도메인을 추가할 수 있다.

수용 기준
1. THE 코어 엔진(분기 로직, LLM 추론, 리포트 템플릿 엔진, 피드백 로깅)은 도메인 지식에 의존하지 않는다.
2. THE 반도체 플러그인(MP 커넥터, SECOM 로더, 소재-결함 KB, 리포트 템플릿)은 정의된 인터페이스를 구현한다.
3. WHEN 새 도메인 플러그인을 등록하면 THEN 코어 코드 수정 없이 동작한다.

## 4. 비기능 요구사항

| ID | 항목 | 요구 |
|---|---|---|
| NFR-1 | LLM | AWS Bedrock(Claude 계열) 사용, 키/리전 환경변수로 주입 |

## 5. 범위 밖 (Out of Scope, 예선)
- 실시간 팹 데이터 스트리밍 연동
- 다국어 리포트(한국어 우선, 필요 시 영어)
- 사용자 인증/멀티테넌시
- 프로덕션급 MLOps 파이프라인

## 6. 가정 & 리스크
| 항목 | 내용 | 완화책 |
|---|---|---|
| 가정 | MP API 키 발급 가능 | 미발급 시 캐시 스냅샷으로 데모 |
| 리스크 | MP에 결함 형성 에너지 직접값 부재 | 안정성 프록시 지표 + 문헌 인용으로 대체, 한계 명시 |
| 리스크 | SECOM 변수 익명화 → 원인 매핑 곤란 | 통계 이상만 규명 + 사용자 매핑 테이블(P2) |
| 리스크 | 2주 일정 | 3-A 최우선, 3-B/E 축소 가능 스코프로 분리 |
| 리스크 | Bedrock 접근 권한/모델 활성화 | 조기 계정 셋업, 프롬프트는 모델 교체 가능하게 추상화 |
